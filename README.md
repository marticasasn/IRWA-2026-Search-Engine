## Part 1: Text Processing and Exploratory Data Analysis

Everything for Part 1 is in **`IRWA_Part1_Text_Processing_EDA.ipynb`**.

### How to run

1. Start Jupyter from the repository root:
   ```bash
   jupyter notebook IRWA_Part1_Text_Processing_EDA.ipynb
   ```
   (or open the notebook in VS Code / JupyterLab).
2. Run all cells in order (**Kernel → Restart & Run All**). The cells depend on each other, so they must be run from top to bottom.
3. When it finishes, the notebook has written **`processed_corpus.json`** to `DATA_DIR`. This file is the input for Part 2.

**Google Colab:** upload the notebook, upload the two data files (or mount Google Drive), install any missing library with
`!pip install wordcloud spacy`, and set `DATA_DIR` to the folder that contains the files (e.g. `"/content/drive/MyDrive/IRWA/"`).

> The NER section (2.13) runs spaCy on a sample of 3,000 descriptions and is the slowest cell. All other cells run in a few seconds/minutes on a laptop.

### What the notebook does

**PART 1: Data preparation**

| Section | Content |
|---------|---------|
| 1.1 Load the corpus | Loads the JSON into a DataFrame, checks missing values (empty strings and empty lists count as missing) and that `pid` is unique. |
| 1.2 Text pre-processing | Pipeline applied to `title`, `description` (and later to the queries): see below. |
| 1.3 Categorical fields | Measures how distinctive `category`, `sub_category`, `brand`, `seller` and `product_details` are, checks where the validation query terms appear, and decides how to index each field (hybrid approach). |
| 1.4 Numerical / boolean fields | Converts `selling_price`, `actual_price`, `discount`, `average_rating` to numbers and `out_of_stock` to boolean. They are stored as attributes for filtering and ranking, **not** indexed as text. |
| 1.5 Final processed corpus | Builds and saves `processed_corpus.json`. |
| 1.6 Sanity check | Checks how many labelled documents of `validation_labels.csv` match all the query terms using only the title vs. using `all_terms`. |

**Text pre-processing pipeline** (function `build_terms(text)`):

1. Lowercasing
2. Removal of URLs and non-ASCII characters (emojis, symbols)
3. Domain normalization of spelling variants (`t-shirt / tshirt / tee → tshirt`, `men's / mens → men`, `slimfit → slim fit`, `polycotton → poly cotton`, ...)
4. Punctuation replaced by a space (so that glued words like `look.Designed` or `full-sleeve` are split)
5. Tokenization with `nltk.word_tokenize`
6. Removal of numbers and 1-character tokens
7. Stop word removal (NLTK English list)
8. Stemming with NLTK `PorterStemmer`

**How each field is handled** (hybrid approach, justified in section 1.3 of the notebook):

| Field | Handling |
|-------|----------|
| `title`, `description` | Merged into the main searchable field `all_terms` |
| `product_details` | Useful keys (fabric, colour, fit, sleeve, ideal for, pattern...) merged into `all_terms`; codes and non-descriptive keys (`Style Code`, `Model Name`, `Size`, ...) excluded |
| `brand` | Merged into `all_terms` and also kept as a separate field |
| `category`, `sub_category`, `seller` | Separate fields only (used for filters/facets, not in the main text) |
| `selling_price`, `actual_price`, `discount`, `average_rating`, `out_of_stock` | Cleaned numeric/boolean attributes (`*_num`), not indexed as text. Missing discounts are computed from the prices; missing ratings are kept as `NaN` (not 0) |

**PART 2: Exploratory Data Analysis** (sections 2.1 – 2.14): word count distributions, average sentence length,
vocabulary size after each pre-processing step and Zipf's law, most frequent terms and word clouds, categories,
top brands and sellers, best rated brands/sellers, prices and discounts, ratings and correlations, product rankings
by rating/price/discount, out-of-stock distribution, product detail attributes, duplicated titles, named entity
recognition with spaCy, and a summary of the findings.

### Output: `processed_corpus.json`

One JSON document per line (JSON Lines), one line per product (28,080 lines), with these fields:

| Group | Fields |
|-------|--------|
| Identifier + original output fields (unchanged, used to display the results) | `pid`, `title`, `description`, `brand`, `category`, `sub_category`, `product_details`, `seller`, `out_of_stock`, `selling_price`, `discount`, `actual_price`, `average_rating`, `url` |
| Cleaned numerical values (for filtering and ranking) | `selling_price_num`, `actual_price_num`, `discount_num`, `average_rating_num` |
| Processed terms (lists of stems) | `all_terms` (main searchable field), `title_terms`, `description_terms`, `details_terms`, `brand_terms`, `category_terms`, `sub_category_terms`, `seller_terms` |

It can be loaded in the next parts with:

```python
import pandas as pd
corpus = pd.read_json("processed_corpus.json", lines=True)
```

### Configuration options

All options are plain variables in the notebook; change them and re-run all cells.

| Option | Cell / section | Default | Effect |
|--------|----------------|---------|--------|
| `DATA_DIR` | 0. Setup | `"./"` | Folder containing the input files and where `processed_corpus.json` is written |
| `CORPUS_PATH`, `VALIDATION_PATH`, `OUTPUT_PATH` | 0. Setup | `DATA_DIR + <file name>` | Paths of the corpus, validation labels and output file |
| `NORMALIZATION_RULES` | 1.2 | list of regex rules | Spelling variants unified before tokenization. Add/remove `(pattern, replacement)` pairs to change the normalization |
| `STOP_WORDS` | 1.2 | NLTK English stop words | Stop word list used by `build_terms` |
| `stemmer` | 1.2 | `PorterStemmer()` | Stemmer used by `build_terms` (e.g. replace with `nltk.stem.SnowballStemmer("english")`) |
| `EXCLUDED_DETAIL_KEYS` | 1.3 | `Style Code`, `Model Name`, `Pack of`, ... | Keys of `product_details` that are **not** added to the searchable text |
| `QUERIES` | 1.3 | the two validation queries | Queries used in the field analysis (1.3) and the sanity check (1.6) |
| `OUTPUT_FIELDS`, `NUMERIC_FIELDS`, `TERM_FIELDS` | 1.5 | see notebook | Columns saved in `processed_corpus.json` |
| NER sample size / seed | 2.13 | `3000`, `random_state=42` | Number of descriptions analysed with spaCy (increase for more coverage, decrease for speed) |

### Main functions

| Function | Section | Description |
|----------|---------|-------------|
| `is_empty(value)` | 1.1 | `True` if a value is `None`, `NaN`, an empty string or an empty list |
| `clean_text(text)` | 1.2 | Steps 1–4 of the pipeline: lowercase, remove URLs/non-ASCII, normalize variants, punctuation → space |
| `build_terms(text)` | 1.2 | Full pre-processing pipeline; returns the list of terms of a text. **Use it on queries too** |
| `flatten_details(details)` | 1.3 | Converts the list of one-key dicts in `product_details` into one dict |
| `details_to_text(details_dict)` | 1.3 | Joins the values of the useful `product_details` keys into one text |
| `parse_number(value)` | 1.4 | Parses strings like `"2,999"` → `2999.0`, `"69% off"` → `69.0`, `""` → `NaN` |
| `contains_all(doc_terms, query_terms)` | 1.6 | Conjunctive (AND) match: `True` if the document contains every query term |
| `split_sentences(text)` | 2.2 | Sentence splitting that also handles sentences glued without a space |
| `top_terms(term_lists, n)` | 2.4 | Most frequent terms of a field |
| `readable_words(texts)` | 2.4 | Unstemmed word frequencies for the word clouds |
| `best_rated(column, min_products, n)` | 2.6 | Best rated brands/sellers with at least `min_products` rated products |

Example of using the pre-processing on a query (after running sections 0–1.2):

```python
build_terms("Men's Slim Fit T-Shirt")
# ['men', 'slim', 'fit', 'tshirt']
```
